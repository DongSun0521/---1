# Combat V2-8C：正式队伍与角色属性接入

V2-8C只把正式角色的只读战斗快照接入“不结算预览”，没有开始V2-8D。V1仍是默认正式
战斗；V2结果不会发放经验、奖励或资源，不会写回生命与伤情，不会推进远征，也不会调用
`SaveSystem`。

## 数据流和读取边界

正式主界面明确选择V2后，数据按以下单向流程流动：

```text
CharacterRoster（GameState只读API）
  → FormationDefenseFormalPartySource
  → 深拷贝正式队伍快照
  → FormationDefenseStatScaleAdapter（正式成长比例 × 冻结V2职业基准）
  → V2战斗就绪属性
  → V2-8A纯数据契约与Adapter
  → Battle Router / Preview Host
  → 动态1～4名V2运行角色
  → 正式稳定ID关联的纯事实结果
  → 不结算调试摘要
```

`FormationDefenseFormalPartySource`是唯一读取正式角色的接入边界。它使用：

- `GameState.get_character_ids()`：取得由`CharacterRoster`按正式`party_slot`排序的1～4人队伍；
- `GameState.get_roster_character()`：读取稳定ID、角色类型、名称、职业、技能、表现、伤情和槽位；
- `GameState.get_final_combat_stats()`：读取正式侧已经完成计算的最终属性；
- `GameState.get_profession_display_name()`：读取正式职业显示名。

最终属性入口内部已经包含等级成长、装备、村庄加成、伤情和当前远征料理。V2不复制这些
公式。V2只做两个战斗模型之间显式、可追踪的尺度换算，不重新结算任何成长来源，也不
叠加隐藏倍率。正式快照和请求均为深拷贝；开始战斗后修改运行角色不会
影响`CharacterRoster`。

空队伍、重复或空ID、生活角色、非出战角色、重复/非法槽位、不支持职业，以及缺失、
NaN、无穷、非正生命或非正攻速都会阻止V2启动。失败不会自动改走V1，也不会补原型角色。

## 正式字段到V2字段

| 正式快照 | V2请求/运行字段 | 规则 |
|---|---|---|
| `character_id` | `character_id` / 运行节点ID / 结果ID | 原样使用稳定ID，不按数组位置关联 |
| `display_name` | `display_name` | 角色主体、调试与结果摘要显示正式名称 |
| `profession_id` | 集中职业兼容映射 | 只按职业映射，不按角色ID或队伍槽位 |
| `party_slot` | 固定部署槽位 | 槽位0～3依次为`middle_c4/top_c4/bottom_c2/middle_c2` |
| 最终`max_hp` | `max_health`和初始`current_health` | 按“正式最终/职业参考”比例缩放冻结V2生命；预览每局从最大生命开始 |
| 最终`attack` | `attack_damage`或`heal_amount` | 按正式攻击比例缩放冻结V2攻击/治疗；医生仍只治疗 |
| 最终`attack_speed` | V2就绪`attack_speed`→`action_interval` | 先按正式攻速比例缩放冻结V2间隔，再把V2就绪频率写入契约 |
| 最终`defense` | 仅保留在请求 | 当前V2角色没有防御减伤入口，因此不伪造第二套机制 |
| 最终`speed/crit_*` | 仅保留在请求 | 当前V2角色未消费，不引入隐藏修正 |
| `skill_ids` | `equipped_skill_ids` | 作为正式技能事实保留，不冒充已接入正式技能效果 |
| `battle_visual_id` | 运行调试元数据 | 保留正式表现ID；本阶段仍使用V2程序化角色表现 |
| `injury_state` | 请求快照 | 伤情对最大生命的影响已包含在正式最终属性中，不重复结算 |

V2-8A契约没有独立“当前生命”或“治疗强度”字段。因此预览初始生命明确等于最终最大生命；
医生把正式最终攻击映射为V2自动治疗基础值。正式`healing_art`技能ID会随请求保留，但其
V1技能效果没有被重复接入V2。

## V2-8C-R属性尺度

V1是回合制模型，没有“每秒攻击次数”或秒制普攻冷却。`BattleSystem`每轮为每个存活单位
生成一次行动，`speed`只决定该轮排序；当前`attack_speed`随正式属性保留，但V1行动循环
不读取它。因此把正式攻速3/7/5/6直接取倒数，并不是复用V1公式，而是把回合排序尺度
误当成V2实时频率。

正式系统目前没有按职业读取参考属性的API。尺度适配器以职业为键，记录
`CharacterDatabase._build_characters()`当前四个正式基础定义作为接口参考快照：

| 正式职业 | 参考生命 | 参考攻击/治疗 | 参考攻速 |
|---|---:|---:|---:|
| `guard` | 40 | 6 | 3 |
| `ranger` | 26 | 8 | 7 |
| `mage` | 22 | 7 | 5 |
| `healer` | 24 | 4 | 6 |

冻结V2基准不复制到适配器，而是实时只读
`PrototypeConfig.get_character_definition(v2_role_id)`：

| V2职业 | 基准生命 | 基准攻击/治疗 | 基准间隔 |
|---|---:|---:|---:|
| `guard` | 150 | 攻击18 | 0.80秒 |
| `hunter` | 90 | 攻击16 | 0.65秒 |
| `mage` | 80 | 攻击28 | 1.10秒 |
| `doctor` | 100 | 治疗16 | 0.75秒 |

转换公式集中在`systems/formation_defense_stat_scale_adapter.gd`：

```text
生命比例 = 正式最终生命 / 正式职业参考生命
攻击比例 = 正式最终攻击 / 正式职业参考攻击
攻速比例 = 正式最终攻速 / 正式职业参考攻速

V2运行生命 = 冻结V2基准生命 × 生命比例
V2运行攻击或治疗 = 冻结V2基准攻击或治疗 × 攻击比例
V2运行间隔 = 冻结V2基准间隔 / 攻速比例
```

生命和攻击只在现有整数运行时边界做一次确定性四舍五入；比例和攻击间隔保留浮点数。
范围不参与比例转换，仍为82/500/450/330。请求契约版本保持v1；其中`final_stats`现在是
可直接供V2运行的属性，正式原值、参考值、比例、V2基准和运行结果只保留在接入边界的
纯数据调试报告中，不进入结算或存档。

适配器没有成长封顶或隐藏软上限。专项除五倍参考属性压力样本外，还按正式等级上限50和
`COMBAT_LEVEL_GROWTH_BY_CHARACTER`抽样了仅含基础与等级成长的上限值：

| 职业 | Lv.50正式生命/攻击/攻速 | 对应V2生命/效果/间隔 |
|---|---|---|
| 战士 | 432 / 55 / 3 | 1620 / 165 / 0.8秒 |
| 游侠 | 222 / 106 / 56 | 768 / 212 / 0.08125秒 |
| 法师 | 218 / 154 / 5 | 793 / 616 / 1.1秒 |
| 医生 | 269 / 53 / 55 | 1121 / 212治疗 / 约0.08182秒 |

这些数值尚未包含装备、村庄、特性、伤情或餐食。结果均为有限值，但游侠和医生的正式
`speed`等级成长也会进入`attack_speed`，从而在V2实时模型中把间隔压到约0.08秒；继续
叠加装备等来源可能产生明显DPS/治疗频率膨胀。该风险留待正式成长平衡阶段处理，本阶段
不擅自加上限。

## 四职业兼容

集中映射位于`systems/formation_defense_profession_compatibility.gd`：

| 正式职业ID | V2角色 | 普攻 | V2大招兼容ID | V2范围 |
|---|---|---|---|---:|
| `guard` | `guard` | 近战 | `ground_shock` | 82 |
| `ranger` | `hunter` | 远程 | `precision_snipe` | 500 |
| `mage` | `mage` | 远程 | `arcane_blast` | 450 |
| `healer` | `doctor` | 治疗 | `group_heal` | 330 |

当前大招、颜色、能量和行为来自冻结V2职业能力，调试中明确标为
“V2职业兼容能力（非正式技能效果接入）”。映射不会写回正式技能或角色数据，并为未来
V2原生技能ID保留了集中入口。

## 动态队伍、结果与清理

接入模式按请求动态重建1～4名角色。空槽位不生成节点，队伍顺序只决定部署位置；稳定ID
贯穿角色节点、集火/治疗目标和结果。医生缺席时不会生成幽灵治疗者，单人队伍、倒下、
重开和中止均沿同一运行逻辑。返回主界面时Host、运行角色和完整请求快照都会释放。

独立运行`prototype/formation_defense/scenes/formation_defense_prototype.tscn`时不会进入接入
模式，仍生成冻结的`guard/hunter/mage/doctor`四名原型角色，保持历史测试和调试能力。

结果摘要按稳定ID显示正式名称、倒下、剩余生命、伤害、承伤、治疗和大招次数，并固定提示：

`V2-8C正式队伍预览未执行正式结算`

`settlement_id`仍只生成和显示，不消费、不保存。

## 人工检查

1. 在正式角色界面确认当前战斗队伍、名称和顺序。
2. 从正式主界面选择“V2接入预览（不结算）”，点击“启动所选”。
3. 查看入口调试文字，逐项核对正式最终值、职业参考值、三个比例、冻结V2基准、最终V2
   运行生命/攻击或治疗/间隔和范围。
4. 完成一局或点击“退出预览”，核对摘要中的正式角色ID和结果。
5. 返回后确认经验、装备、伤情、资源、远征进度和存档均未变化。
6. 将正式队伍调整为1～3人后再次启动，确认没有原型角色补位。
7. 重启游戏，确认入口仍默认V1。

专项入口：`tools/smoke_v2_8c_formal_party_mapping.gd`与
`tools/smoke_v2_8c_r_stat_scale_adapter.gd`。
