## 1. 当前结论

《冒险村》已经从最小战斗原型推进为一套可运行、可存档、可回归验证的
“村庄后勤 + 节点远征 + 回合战斗 + 双角色体系”原型。

当前核心循环：

```text
配置生活角色岗位
    -> 农田、食物制造、锻造、医院和建设按游戏日推进
    -> 配置1～4名战斗角色、装备、远征口粮、药品和料理
    -> 在森林/遗迹节点移动、采集和战斗
    -> 远征行动同步推进村庄生产
    -> 返回或失败后结算资源、伤势、经验和Boss进度
    -> 招募/培养生活角色、培养战斗角色、制造装备和强化村庄
    -> 再次远征
```

截至Stage 12F，以下主线已经闭环：

- 统一游戏日与结构化日报；
- 七座建筑外显和统一建筑操作入口；
- 农田种植、食物制造、装备锻造、医院制药/治疗；
- 节点式远征、补给、采集、普通战和树精Boss；
- 四名战斗角色、正式编队、装备、技能、特性、伤势和等级成长；
- 正式生活角色、五项生活属性、特性、岗位、生产效率和工作成长；
- 三候选生活角色招募池、锁定、刷新、容量、正式锁定和确认解雇；
- 战斗及生活成长反馈、头像、状态文字、通知和误操作保护；
- v6存档及v0～v5迁移；
- Stage 8～12F专项回归和Stage 12总集成测试。

当前仍是原型而非完整商业版本。第二章节、火元素Boss实战、科研所和资源
收集所的正式生产玩法、正式存档UI、自动存档、疲劳心情、自动排班、角色
关系、完整剧情、正式平衡和最终美术仍未完成。

## 4. 当前可玩内容

### 4.1 村庄主界面

- 顶部显示日期、粮食、远征口粮、药品、矿石、草药和Boss核心；
- 村庄地图展示七座建筑；
- 左侧总览展示目标、队伍生命、后勤状态和最近提示；
- 建筑可以直接点击，也可通过总览快捷按钮进入常用生产页面；
- 底部功能栏打开战斗角色和生活角色页面；
- 生活角色页头部可以进入招募页面；
- “开始远征”打开远征准备。

### 4.2 村庄生产

- 农田可为地块选择小麦或药草；
- 食物制造所可生产口粮和两类料理；
- 医院可制药或治疗一名伤员；
- 武器制造所可制造装备；
- 建设项目可升级农田/医院或强化固定战斗队；
- 生活角色岗位会影响最终生产倍率和额外产出；
- 有效完成后会产生角色工作经验和最近工作结果。

### 4.3 战斗角色

- 默认正式角色：阿盾、林羽、米娅、露娜；
- 可配置1～4人出战和顺序；
- 有等级、经验、最终属性、技能、特性、装备、伤势和当前生命；
- 升级上限50；
- 战斗结算只奖励实际出战角色；
- 远征或战斗期间不能改队。

### 4.4 生活角色与招募

- 默认正式生活角色：阿禾、阿铁、小药；
- 五项生活属性范围0～100；
- 可分配到建筑岗位、替换、撤下、锁定或确认解雇；
- 岗位决定工作状态、效率和升级属性方向；
- 招募池固定3名候选；
- 候选可锁定，刷新只替换未锁定候选；
- 品质影响初始属性、特性数量和招募费用；
- 生活角色容量为 `3 + 2 × 所有民居实例等级总和`；
- 候选和正式角色保存稳定头像路径，缺失时回退默认头像。

### 4.5 远征

- 当前是一条森林/遗迹线性节点路线；
- 支持移动、采集、战斗和主动返回；
- 出发时携带远征口粮、药品和可选料理；
- 移动/采集推进一天，村庄同步运转；
- 普通战为史莱姆，Boss为树精守卫；
- 正常返回和失败使用不同物资/伤势结算；
- Boss胜利获得核心并完成当前MVP目标。

### 4.6 战斗

- 回合制，速度决定行动顺序；
- 支持普通攻击、主动技能、防御和药品；
- 敌人AI和Boss行动由系统计算；
- 装备词条可修改战斗计算中的指定步骤；
- 表现层播放角色动画、投射物、特效、音效、震动、闪光和浮字；
- 结算页面显示每名实际出战角色的成长结果。

### 4.7 存档

当前存档版本：

```text
SaveSystem.CURRENT_SAVE_VERSION = 6
```

已保存：

- 日期、资源和堆叠物品；
- 正式角色、等级、经验、属性、头像、装备、编队、伤势和岗位；
- 建筑、农田、食物制造、锻造、医院和建设状态；
- 远征、战斗、Boss和统计；
- 生活招募候选、候选锁定和随机状态；
- 通知和建筑最近工作结果。

加载支持v0～v5迁移。缺失头像、非法等级/经验/属性、负资源、损坏候选、
损坏通知和无效岗位引用会被修复或清理。

当前只有保存/读取API和默认单文件路径，没有正式存档槽选择界面、自动存档、
备份轮换或云存档。

## 5. 当前权威数据边界

以下边界是Stage 12之后的稳定基线，后续不得另建重复系统：

### 5.1 正式角色

```text
GameState.character_roster / CharacterRoster
```

是全部正式战斗角色和生活角色的唯一真源。

角色等级、经验、头像路径、装备绑定、编队、生活属性、生活特性、正式锁定和
角色侧岗位引用都保存在 `CharacterRecord`。

早期 `adventurers` 和 `character_runtime_states` 只作为兼容快照/适配器，
不能成为新的角色仓库。

### 5.2 岗位运行态

```text
GameState.buildings[*].jobs
```

是岗位槽位和岗位占用的运行态真源。角色侧建筑ID、岗位ID和工作状态是需要
双向校验的角色信息，不可脱离 `buildings[*].jobs` 单独运转。

### 5.3 招募候选

```text
GameState.life_recruitment_state
```

是候选池唯一真源。候选在正式招募前不能写入 `CharacterRoster`。招募成功后
移除候选标记并进入正式角色仓库。

### 5.4 战斗

`BattleSystem` 是伤害、治疗、目标、冷却、词条、死亡和胜负的唯一计算来源。
`BattleView` 只能读取结果并播放表现。

### 5.5 日期和生产

所有正式日期推进都通过：

```gdscript
GameState.advance_day(reason)
```

生产系统不得自行增加日期，同一生产周期不得重复发放产物或工作经验。

### 战斗成长

- 普通胜利：每名实际出战角色40经验；
- Boss胜利：每名实际出战角色100经验；
- 失败：每名实际出战角色10经验；
- 升级需求：`100 + (当前等级 - 1) × 50`；
- 最高50级；
- 满级经验需求为0，新经验不再累积。

### 生活成长

- 基础有效工作经验：10；
- 特性可提供工作经验百分比加成；
- 升级需求与战斗角色使用相同首版曲线；
- 每级目标生活属性+2，最高100；
- 最高50级；
- 同一结算键只能发放一次。

### 招募

- 候选数：3；
- 刷新费用：2粮食；
- 招募费用按品质配置；
- 刷新保留已锁定候选；
- 达到容量后不能继续招募；
- 头像重复不影响生成。

### 队伍与属性

- 战斗队伍人数1～4；
- 角色ID不能重复；
- 生活属性0～100；
- 暴击率0～1；
- 当前生命不超过最终最大生命；
- 资源扣除后不得为负。
