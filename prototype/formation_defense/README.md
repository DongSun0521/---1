# Combat V2：阵型塔防原型

## Combat V2-4：集火与拆阵指挥

V2-4 在 V2-3 怪物组阵基础上增加单一活动指挥目标。运行当前场景后选择
“V2-4 集火/拆阵”、使用推荐部署并开始：左键点击存活敌人下达或替换指挥，
右键或 Esc 取消；左键空白不会取消，HUD 事件通过 `_unhandled_input` 与战场隔离。

- 单体显示“集火目标”，FORMING_A/B 显示“阻止组阵”，完整阵型显示“拆A阵/拆B阵”。
- 指挥只在角色原有合法候选中提升目标优先级；战士阻挡、远程射程和医生治疗规则保持不变。
- 目标暂不合法时保留标记并显示“等待进入射程”，角色继续按 V2-2 规则自动战斗。
- B 阵降为 A 阵后本次指挥立即结束，必须再次点击才能继续拆 A 阵。
- 每次真实攻击结算后，根据同一攻击记录生成纯视觉反馈：游侠为黄白箭矢与橙色拖尾，
  法师为蓝紫光球，战士为约 0.1 秒斩击线；医生不会生成攻击弹体。
- 远程视效按距离取 0.15～0.35 秒飞行时间，使用发射时固定的目标 ID 与终点；
  不参与碰撞、追踪或伤害，胜负和重开会清空全部残留节点。
- `FORMATION_SLOT_MOVE_SPEED = 80.0` 只控制 FORMING_A/B 锁定后的靠拢窗口；完整阵型沿用独立的
  `COMPLETE_FORMATION_SLOT_MAINTENANCE_SPEED = 80.0`，两者不改变普通移动、冲锋阵型倍率、攻击速度或角色冷却。
- 确定性 V2-4 演示复用 V2-3 已锁定的 12 敌人生成计划，不操作也能约 41 秒完成胜利。

指挥状态唯一真源为 `scripts/formation_defense_command_controller.gd`；敌人只保存绘制标记，
角色只把合法候选交给控制器裁决。攻击视效由
`scripts/formation_defense_projectile_visual.gd` 提供。专项检查位于
`tests/smoke_v2_4_focus_command.gd`。

## MVP 验证目标

Combat V2 MVP 用于验证“多路敌人向村庄推进，角色组成防线并自动作战”的核心循环
是否清晰、可操作且值得继续扩展。验证过程应优先关注战场信息可读性、阵型决策和
基础胜负反馈，不接入正式养成经济。

## 当前实现：V2-4

V2-0 建立了可独立运行、可整体删除的原型环境，V2-1 完成三路敌人进攻同一个
村庄入口的基础循环，V2-2 加入角色部署与基础自动战斗。V2-3 在不合并怪物单位
的前提下加入：

- 冲锋怪与盾甲怪两种原型怪物；
- 单体行走、A组阵、A阵展示、B组阵和防守交战五类可调区域；
- 6个配置化刷怪口，其中组阵演示确定性启用5个兼容入口，另保留1个隔离测试入口；
- `spawn_point_id`、`route_id`、`route_group_id` 与
  `formation_route_index`、`blocking_lane_id` 的最低限度职责拆分；
- 80像素等距的5条兼容组阵轨、显式路线索引与可配置的A/B邻轨搜索跨度；
- 同类型、同区域、兼容路线组、路线跨度和二维椭圆距离内的确定性候选匹配；
- 完整A阵一次性确定稳定路线锚点，B阵只使用两个来源A阵的稳定锚点判断跨度；
- 原子锁定成员与槽位，通过双向靠拢形成上下A阵和2×2 B阵；
- 1.5/2.5秒最短时间、槽位容差和8秒会合超时的联合完成条件；
- 锁定靠拢、A阵、B阵的连线、位置/时间综合进度、标识与效果文字；
- 冲锋A/B阵的25%/50%移速加成，以及B阵一次首次控制抵抗；
- 盾甲A/B阵的35%/60%远程减伤，以及B阵30%兼容路线组友军保护；
- 成员死亡、漏怪和原型控制中断后的解散、来源A阵恢复与B阵降级；
- 阵型统计、重开清理和可重复的三路组阵演示。

怪物仍独立移动、受击、阻挡、死亡和漏怪，每名成员分别占用战士阻挡容量。
V2-4 仅增加点击集火、合法候选优先级与拆阵反馈，不包含真实控制技能、大招、
指挥资源、正式波次、奖励或正式运行态接入。

目录约定：

- `scenes/`：原型专用场景；
- `scripts/`：原型专用运行脚本；
- `data/`：后续原型数值和数据资源；
- `tests/`：原型入口、基础循环、自动战斗和隔离边界的自动化检查。

## 当前入口

入口场景：

```text
res://prototype/formation_defense/scenes/formation_defense_prototype.tscn
```

在 Godot 编辑器中打开该场景后选择“运行当前场景”（F6），即可单独启动。也可在
项目根目录运行：

```powershell
tools\godot.bat --path . `
  res://prototype/formation_defense/scenes/formation_defense_prototype.tscn
```

## 操作与测试方案

开始前可选择方案，并可部署0～4名角色：

- **生存演示（V2-1兼容）**：无角色时上、中、下路各2只，共6只；全部漏入后
  村庄剩余4点耐久并进入 `VICTORY`；
- **失守演示（V2-1兼容）**：无角色时上、中、下路各4只，共12只；第10只漏入
  后耐久归零，立即进入 `DEFEAT` 并清理剩余敌人；
- **自动战斗演示（V2-2）**：固定12只三路敌人；空部署时 `DEFEAT`，使用“推荐
  部署”时4名角色均产生有效行动并稳定进入 `VICTORY`；
- **怪物组阵演示（V2-3）**：12只冲锋怪与盾甲怪从5个兼容入口按固定顺序
  出生，基础生成间隔为0.75秒，部分成对批次使用单一`delay_after=0.35`拉开前后
  距离；推荐部署下稳定观察到同轨、跨1轨、跨2轨和前后/上下/斜向配对，以及
  移速、减伤、友军保护、控制抵抗和死亡降级，约41秒完成。

点击角色卡后点击空部署点即可放置；再次点击其他空位会移动所选角色，点击已占用
位置会选中其角色。部署仅在 `READY` 可调整，战斗开始后会锁定。“重新开始”会
保留部署，但恢复角色与敌人的运行态、耐久、计数、阻挡、生成进度和提示；可使用
“清空部署”做无防守对照。这些方案是确定性的原型测试数据，不是正式波次设计。

## V2-3 原型数值

- 敌人：50生命、60移动速度、10攻击伤害、1.0秒攻击间隔、漏怪伤害1；
- 战士：150生命、18伤害、0.8秒间隔、82范围、阻挡2；
- 游侠：90生命、16伤害、0.65秒间隔、340范围；
- 法师：80生命、28伤害、1.1秒间隔、340范围；
- 治疗者：100生命、16治疗、0.75秒间隔、330范围。
- 5条兼容组阵轨：索引0～4，刷怪端纵向间距80像素；另有隔离路线组测试轨；
- A/B邻轨搜索跨度默认均为2（0仅同轨、1允许±1、2允许±2）；
- A组阵二维椭圆半径：X=200、Y=190；最短形成时间1.5秒；
- B组阵二维椭圆半径：X=240、Y=210；最短形成时间2.5秒；
- A槽位上下间距56；B槽位为70×62的2×2方阵；
- 靠拢速度80、槽位容差7、会合超时8秒、组阵前进倍率0.78；
- 冲锋A/B阵：移速倍率1.25/1.50，冲锋B阵首次控制抵抗1次；
- 盾甲A/B阵：远程减伤35%/60%，盾甲B阵兼容路线组内二维240范围友军减伤30%。

数值只为稳定验证链路服务，不代表正式平衡。

## V2-3 代码职责

- `data/formation_defense_config.gd`：五类区域、刷怪口、等距路线/显式索引/路线组
  兼容、邻轨跨度、部署点、角色/敌人数值、确定性生成计划，以及阵型椭圆、时间、
  槽位和效果；
- `scripts/formation_defense_prototype.gd`：部署授权、生成、状态、阻挡协调、统计、
  阵型管理器生命周期、胜负和重开；
- `scripts/formation_defense_character.gd`：角色冷却、确定性选敌、攻击、治疗和
  范围/生命显示，并为普通攻击传递MELEE/RANGED标记；
- `scripts/formation_defense_deployment_slot.gd`：部署点身份、占用状态与交互显示；
- `scripts/formation_defense_enemy.gd`：独立路径移动、生命、阻挡和结算，以及出生
  点、路线组、显式路线索引、阻挡路、当前区域、固定槽位目标和临时steering状态；
- `scripts/formation_defense_formation_group.gd`：原子锁定成员、来源A阵、固定槽位、
  会合中心、稳定路线锚点、初始槽位误差、时间/位置进度、效果和控制抵抗状态；
- `scripts/formation_defense_formation_manager.gd`：统一区域查询、二维候选分配、
  邻轨跨度/稳定锚点筛选、原子锁定、靠拢、超时、完成、中断、降级、保护关系和
  阵型连线；
- `scripts/formation_defense_route_view.gd`：五类区域底色/标签、软路线和多刷怪口；
- `tests/smoke_v2_0_prototype.gd`：入口和隔离基线；
- `tests/smoke_v2_1_basic_loop.gd`：无角色的确定性胜败与重开兼容；
- `tests/smoke_v2_2_auto_combat.gd`：部署、自动战斗、阻挡、结算、连续重开和
  隔离验收；
- `tests/smoke_v2_3_monster_formations.gd`：区域准入、跨度0/1/2、稳定锚点、跨路线
  椭圆配对、原子锁定、固定槽位/超时、A/B阵效果、控制抵抗、降级、两次确定性
  实际演示、重开和隔离验收。

## 与正式系统的隔离原则

- 不替换默认主场景，不注册 Autoload，不增加正式入口；
- 原型运行时不读取或写入 `GameState`；
- 不接入 `CharacterRoster`、`SaveSystem` 或正式存档；
- 不读取正式角色、装备、建筑、战斗场景和正式数值配置；
- 原型运行资源的依赖必须保持在本目录内或使用 Godot 内建资源；
- 后续原型数值统一放入本目录的 `data/`；
- 删除整个 `formation_defense/` 目录后，正式项目应保持原有行为。

## 后续边界

当前没有提前实现自动选择最低血量/阵眼、独立角色指令、角色移动、真实眩晕/击退/
破阵技能、主动技能、大招、能量或指挥资源、村庄支援、正式五波、Boss、更多怪物
类型、奖励、装备、育成、探索或存档接入。
