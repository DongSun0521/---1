# Combat V2：阵型塔防原型

## Combat V2-6A-R：护阵怪真实集火时机验证

调试抽屉中的“V2-6A 护阵怪验证”新增独立敌人配置 `formation_guard`。护阵怪保持91生命、
42普通移动速度、52组阵靠拢速度和普通漏怪伤害；SEARCHING及APPROACHING阶段没有减伤，
真正完成A阵后获得20%玩家伤害减免，完成B阵后改为35%。B阵降级后立即回到20%，成员死亡、
成员移除、Group销毁和重开则同步降低或清除，不与旧远程保护重复叠加。

护阵怪复用程序化史莱姆表现，使用统一钢蓝色身体和头顶小盾牌标记；完整A阵显示单层轻量
护盾环，完整B阵显示双层护盾环，靠拢阶段不显示护盾；真实FORMING_B期间额外显示细蓝灰虚线和
“B阵靠拢预警”，完成、取消或成员死亡后立即消失。调试目标信息显示profile ID、名称、生命、
阵型状态、当前实际减伤和阵型ID。三波验证计划为2/4/16只，共22只：第一波观察A阵，第二波
观察B阵，第三波由4只护阵怪先行、12只普通怪从第5秒起每1.2秒错时跟进。初始倒计时3秒、
波间倒计时3秒，总时长约104秒。

玩家当前只有“集火阵型成员”这一公开指令：左键选择成员后，角色通过正常攻击击杀该成员，
阵型才会自然降级或解体；不存在可在击杀前独立执行的强制破阵指令。旧“只集火/先拆阵再集火”
对照曾直接调用内部阵型中断接口，1.90秒与3.10秒首杀差异无效，已由V2-6A-R删除。

固定种子真实对照（两种操作均只调用同一鼠标点击入口一次）：无人操作VICTORY、104.6秒、
22击杀、0漏怪、耐久10，B阵累计2.3组秒；成阵后集火VICTORY、104.6秒、22击杀、0漏怪、
耐久10，指令时减伤35%，指令至首杀/自然破阵3.10秒，B阵累计4.7组秒、减免143伤害；成阵前
拦截VICTORY、104.6秒、22击杀、0漏怪、耐久10，指令时减伤0%，指令至首杀/自然破阵2.50秒，
B阵累计3.1组秒、减免128伤害。三种模式B阵尝试/完成均为2/2，因此提前集火未阻止成阵，
但稳定缩短高减伤阶段并减少15点减免伤害。两次靠拢窗口实测约1.0秒和0.2秒，仍偏短；本轮
保留2/4/16三波配置和锁定数值，以真实记录该可读性限制，不伪造“成功阻止成阵”结论。
专项检查位于`tests/smoke_v2_6a_formation_guard.gd`，不包含突袭怪或完整V2-6混合波次。

## Combat V2-5C：3～4分钟节奏验证

调试抽屉中的“V2-5C 3～4分钟节奏验证”复用V2-5B调度器，以六波、44只现有敌人形成
“开场熟悉—战场展开—组阵来袭—错峰推进—持续高压—最终高潮”。本方案使用独立节奏配置，
不改变V2-5B和旧演示的单位数值、路线几何或组阵规则。

WaveDirector记录每波起止时间、生成/击杀/漏怪、活动峰值、A/B完成、中断、降级、清理尾巴，
并每5秒采样活动敌人数。第二轮为该方案独立配置91生命、42移动速度、52靠拢速度和12像素
完成阈值；V2-5B及旧演示继续使用原数值。配对锁定阶段只显示“靠拢”文字，正式连线与轮廓
仅在成员进入阈值并切换为COMPLETE后显示。调试抽屉显示累计时间、当前波时长与峰值、阵型次数、耐久、最长空场
及最近压力采样。专项中的旧确定性内部控制路径仅用于锁定历史结果，不代表玩家拥有独立破阵指令。
检查位于`tests/smoke_v2_5c_battle_pacing.gd`。

最终人工验收确认：前五波整体节奏合适、没有明显拖沓；第六波明显变忙并形成最终高潮，人工
操作时第六波漏掉3只怪，当前压力已经足够。因此V2-5C锁定为怪物生命91、普通移动速度42、
组阵靠拢速度52、阵位完成阈值12逻辑像素、初始倒计时3秒、波间倒计时4秒、六波共44只。
确定性基线为：无人运行VICTORY、约227.8秒、村庄耐久4/10；基础指挥VICTORY、约227.0秒、
村庄耐久7/10。当前不再调整生命、移速、组阵速度、波次数量和生成节奏。

阵型统计统一使用历史完成事件口径：每次首次进入FORMED_A或FORMED_B各累计一次；A阵后续
参与B阵、被中断、降级或被消灭都不会倒扣A阵历史完成数。当前活动阵型与累计完成次数分开，
每波完成数之和必须等于全局累计完成数。

## Combat V2-5B：配置化波次与子波次调度

调试抽屉中的“V2-5B 波次验证”使用独立 `formation_defense_wave_director.gd` 驱动三波结构化演示。
调度器只决定生成时间、敌人配置、刷怪口和轨道，并通过现有 `spawn_enemy_for_route()` 入口生成；
移动、阻挡、自动战斗、组阵、集火和结算仍由既有系统负责。
验证方案通过生成组的可选 `max_health` 覆盖把冲锋怪设为100、盾甲怪设为120，避免修改旧方案
使用的全局默认血量，同时为组阵保留更清楚的观察窗口。

状态依次为 `IDLE → COUNTDOWN → SPAWNING → CLEANUP`。本波所有任务生成完、且本波敌人全部
击杀或漏怪后才进入下一次 `COUNTDOWN`；最后一波清理完成后进入 `COMPLETED`。失败进入
`STOPPED` 并清除待生成事件。固定种子的独立 `RandomNumberGenerator` 保证相同输入得到相同轨迹。

左上紧凑 HUD 显示波次、倒计时、生成或清理状态；调试抽屉显示子波次、下一事件、本波及全场统计。
专项检查位于 `tests/smoke_v2_5b_wave_schedule.gd`。该三波方案只验证结构，不代表最终时长或压力曲线。

## Combat V2-4：集火与击杀后破阵反馈

V2-4 在 V2-3 怪物组阵基础上增加单一活动指挥目标。运行当前场景后选择
“V2-4 集火与破阵反馈”、使用推荐部署并开始：左键点击存活敌人下达或替换集火指挥，
右键或 Esc 取消；左键空白不会取消，HUD 事件通过 `_unhandled_input` 与战场隔离。

- 单体显示“集火目标”，FORMING_A/B 显示“成阵前拦截”，完整阵型显示“集火A/B阵成员”。
- 指挥只在角色原有合法候选中提升目标优先级；战士阻挡、远程射程和医生治疗规则保持不变。
- 目标暂不合法时保留标记并显示“等待进入射程”，角色继续按 V2-2 规则自动战斗。
- 目标成员被正常击杀后，阵型自然降级或解体并显示“击杀后破阵”反馈；这不是独立破阵命令。
- 每次真实攻击结算后，根据同一攻击记录生成纯视觉反馈：游侠为黄白箭矢与橙色拖尾，
  法师为蓝紫光球，战士为约 0.1 秒斩击线；医生不会生成攻击弹体。
- 远程视效按距离取 0.15～0.35 秒飞行时间，使用发射时固定的目标 ID 与终点；
  不参与碰撞、追踪或伤害，胜负和重开会清空全部残留节点。
- `FORMATION_SLOT_MOVE_SPEED = 80.0` 只控制 FORMING_A/B 锁定后的靠拢窗口；完整阵型沿用独立的
  `COMPLETE_FORMATION_SLOT_MAINTENANCE_SPEED = 80.0`，两者不改变普通移动、冲锋阵型倍率、攻击速度或角色冷却。
- 确定性 V2-4 演示复用 V2-3 已锁定的 12 敌人生成计划，不操作也能约 41 秒完成胜利。

指挥状态唯一真源为 `scripts/formation_defense_command_controller.gd`；敌人只保存绘制标记，
角色只把合法候选交给控制器裁决。攻击视效由
`scripts/formation_defense_projectile_visual.gd` 提供。专项检查位于
`tests/smoke_v2_4_focus_command.gd`。

## MVP 验证目标

Combat V2 MVP 用于验证“多路敌人向村庄推进，角色组成防线并自动作战”的核心循环
是否清晰、可操作且值得继续扩展。验证过程应优先关注战场信息可读性、阵型决策和
基础胜负反馈，不接入正式养成经济。

## 当前实现：V2-6A

V2-0 建立了可独立运行、可整体删除的原型环境，V2-1 完成三路敌人进攻同一个
村庄入口的基础循环，V2-2 加入角色部署与基础自动战斗。V2-3 在不合并怪物单位
的前提下加入：

- 冲锋怪与盾甲怪两种原型怪物；
- 单体行走、A组阵、A阵展示、B组阵和防守交战五类可调区域；
- 6个配置化刷怪口，其中组阵演示确定性启用5个兼容入口，另保留1个隔离测试入口；
- `spawn_point_id`、`route_id`、`route_group_id` 与
  `formation_route_index`、`blocking_lane_id` 的最低限度职责拆分；
- 80像素等距的5条兼容组阵轨、显式路线索引与可配置的A/B邻轨搜索跨度；
- 同类型、同区域、兼容路线组、路线跨度和二维椭圆距离内的确定性候选匹配；
- 完整A阵一次性确定稳定路线锚点，B阵只使用两个来源A阵的稳定锚点判断跨度；
- 原子锁定成员与槽位，通过双向靠拢形成上下A阵和2×2 B阵；
- 1.5/2.5秒最短时间、槽位容差和8秒会合超时的联合完成条件；
- 锁定靠拢、A阵、B阵的连线、位置/时间综合进度、标识与效果文字；
- 冲锋A/B阵的25%/50%移速加成，以及B阵一次首次控制抵抗；
- 盾甲A/B阵的35%/60%远程减伤，以及B阵30%兼容路线组友军保护；
- 成员死亡、漏怪和原型控制中断后的解散、来源A阵恢复与B阵降级；
- 阵型统计、重开清理和可重复的三路组阵演示。

怪物仍独立移动、受击、阻挡、死亡和漏怪，每名成员分别占用战士阻挡容量。
V2-4 仅增加点击集火、合法候选优先级与击杀后破阵反馈，不包含真实控制技能、大招、
指挥资源、正式波次、奖励或正式运行态接入。
V2-5完成全屏调试布局、配置化波次和战术节奏；V2-6A只增加配置化护阵怪及短战术对照，
没有加入突袭怪或改动V2-5C锁定基线。

目录约定：

- `scenes/`：原型专用场景；
- `scripts/`：原型专用运行脚本；
- `data/`：后续原型数值和数据资源；
- `tests/`：原型入口、基础循环、自动战斗和隔离边界的自动化检查。

## 操作与测试方案

开始前可选择方案，并可部署0～4名角色：

- **生存演示（V2-1兼容）**：无角色时上、中、下路各2只，共6只；全部漏入后
  村庄剩余4点耐久并进入 `VICTORY`；
- **失守演示（V2-1兼容）**：无角色时上、中、下路各4只，共12只；第10只漏入
  后耐久归零，立即进入 `DEFEAT` 并清理剩余敌人；
- **自动战斗演示（V2-2）**：固定12只三路敌人；空部署时 `DEFEAT`，使用“推荐
  部署”时4名角色均产生有效行动并稳定进入 `VICTORY`；
- **怪物组阵演示（V2-3）**：12只冲锋怪与盾甲怪从5个兼容入口按固定顺序
  出生，基础生成间隔为0.75秒，部分成对批次使用单一`delay_after=0.35`拉开前后
  距离；推荐部署下稳定观察到同轨、跨1轨、跨2轨和前后/上下/斜向配对，以及
  移速、减伤、友军保护、控制抵抗和死亡降级，约41秒完成。

点击角色卡后点击空部署点即可放置；再次点击其他空位会移动所选角色，点击已占用
位置会选中其角色。部署仅在 `READY` 可调整，战斗开始后会锁定。“重新开始”会
保留部署，但恢复角色与敌人的运行态、耐久、计数、阻挡、生成进度和提示；可使用
“清空部署”做无防守对照。这些方案是确定性的原型测试数据，不是正式波次设计。

## 与正式系统的隔离原则

- 不替换默认主场景，不注册 Autoload，不增加正式入口；
- 原型运行时不读取或写入 `GameState`；
- 不接入 `CharacterRoster`、`SaveSystem` 或正式存档；
- 不读取正式角色、装备、建筑、战斗场景和正式数值配置；
- 原型运行资源的依赖必须保持在本目录内或使用 Godot 内建资源；
- 后续原型数值统一放入本目录的 `data/`；
- 删除整个 `formation_defense/` 目录后，正式项目应保持原有行为。

## 后续边界

当前没有提前实现自动选择最低血量/阵眼、独立角色指令、角色移动、真实眩晕/击退/
破阵技能、主动技能、大招、能量或指挥资源、村庄支援、正式五波、Boss、突袭怪、
治疗怪、远程怪、奖励、装备、育成、探索或存档接入。
